# Classify Leaves：V1–V8 实验复盘

## 1. 实验目标与数据概况

本实验面向 Kaggle **Classify Leaves** 叶片分类任务，目标不是只得到一次较高分数，而是完整经历以下流程：

1. 自定义数据集与预处理；
2. 从零实现并训练 ResNet18；
3. 使用交叉验证选择训练轮数和超参数；
4. 使用全部训练样本重新训练；
5. 保存模型、预测测试集并生成提交文件；
6. 通过版本迭代分析验证曲线震荡、BatchNorm 和学习率调度之间的关系。

数据集共有 18,353 张有标签训练图片、8,800 张测试图片和 176 个类别。各类别样本数最少 51、最多 353，均值约 104.28，说明数据并非完全均衡，因此正式实验最终采用分层 K 折。

> 口径说明：V1–V7 主要用于第一折上的快速探索，不能视为正式五折成绩；V8 才完成完整的五折交叉验证。文中的单折结果主要用于分析现象，不应与 V8 的五折均值直接比较。

## 2. 八个版本总览

| 版本 | 核心变化 | 发现的问题 | 引出的猜想 | 下一步改进 |
|---|---|---|---|---|
| V1 | 从零 ResNet18；Resize + ToTensor；随机 K 折；固定学习率 | 泛化不足，验证曲线明显波动 | 缺少标准化和增强；随机划分可能使类别比例不稳定 | 加入数据增强与手工标准化 |
| V2 | 加入 RGB 均值/标准差、翻转和旋转 | 训练持续变好，但验证准确率仍会突然大幅下降 | 可能是未分层划分，也可能是 BatchNorm 运行统计量或学习率过高 | 改用 StratifiedKFold，并单独检查 BN |
| V3 | 改用分层五折；进行 `update_bn` 诊断 | 分层后仍有大幅震荡；重新校准 BN 后准确率显著恢复 | 类别比例不是主因，BN running statistics 滞后是重要原因 | 改善残差支路、初始化和学习率调度；测试逐轮 BN 校准 |
| V4 | Conv+BN 捷径、Kaiming 初始化、余弦退火；每轮 `update_bn` 后再验证 | 校准后的曲线明显平稳，但计算成本很高 | 学习率下降后特征分布会变稳，也许不必每轮校准 BN | 移除每轮 `update_bn` 做对照 |
| V5 | 保留 V4 其他设置，取消每轮 `update_bn` | 早中期仍波动，但后期原始验证准确率稳定到约 93% | 低学习率尾段本身足以让模型和 BN 统计量稳定 | 测试更大 batch 是否进一步降低统计噪声 |
| V6 | batch size 64 → 128 | 验证最优约 91.75%，反而低于 V5，且震荡未消失 | 大 batch 虽降低批统计噪声，但每轮参数更新次数也减半 | 延缓学习率下降，给大 batch 更多高学习率训练时间 |
| V7 | 保持 30 轮，`T_max` 30 → 60 | 第 30 轮学习率仍约 0.025，最终验证约 85.34%，明显未收敛 | 调度过慢，缺少低学习率精调阶段 | 回到 batch 64，并把训练延长到 40 轮 |
| V8 | batch 64、40 轮、`T_max=40`；完整分层五折 | 最优点仍靠近调度末端，但五折结果已经稳定 | 当前最主要需求是完整低学习率尾段，而不是反复校准 BN | 以第 39 轮重训全数据并生成提交文件 |

## 3. 版本演化详解

### V1：建立完整基线

V1 的重点是先把端到端流程跑通：读取 `train.csv/test.csv`、定义 `LeavesDataset`、将图片统一到 224×224、从零搭建 ResNet18、随机划分 K 折并训练验证。

这一版只使用 `Resize + ToTensor`，没有数据增强和输入标准化；优化器使用 SGD，初始学习率为 0.05。它证明了数据、网络和训练循环能够正常工作，但验证准确率存在明显波动，且模型容易记住训练图片。

由此产生两个初步猜想：

- 输入分布未标准化，使优化过程更困难；
- 没有数据增强，模型对叶片方向、姿态等变化不够鲁棒。

因此 V2 将重点放在数据预处理上。

### V2：加入数据增强和手工标准化

V2 使用全部训练图片统计 RGB 三通道均值与标准差，并在训练、验证和测试变换中统一执行 `Normalize`。训练集另外加入：

- `RandomHorizontalFlip(p=0.5)`；
- `RandomVerticalFlip(p=0.5)`；
- `RandomRotation(15°)`。

验证集和测试集只做确定性的 Resize、ToTensor 和 Normalize。为保证同一张图片在 K 折训练与验证中使用不同变换，创建了两个内容相同但 transform 不同的 Dataset，再用相同索引分别构造训练和验证 Subset。

这一版训练指标继续改善，但验证准确率仍会发生明显跳变。例如第一折第 27 轮曾达到约 80.44%，第 30 轮又下降到约 65.78%。这说明数据增强和标准化是必要改进，却不是震荡的完整解释。

当时出现了两个新猜想：

1. 普通随机 K 折可能让某些类别在训练集或验证集中抽得偏多、偏少；
2. BatchNorm 在 `eval()` 时使用的 `running_mean/running_var` 可能没有跟上内部特征分布的变化。

### V3：分层划分与 BatchNorm 定位实验

V3 将随机划分改为 `StratifiedKFold`。它保证每折尽量维持原始类别比例，适合本任务这种多类别、各类样本量不同的数据。

然而，分层后验证曲线仍然会突然下降。这否定了“震荡主要由未分层划分造成”的猜想。分层能提高各折的可比性，却无法解释同一折在相邻 epoch 间的大幅跳变，因为同一折的验证样本根本没有变化。

随后使用训练折中**无随机增强**的图片重新统计 BatchNorm：

| 状态 | 训练准确率 | 验证准确率 |
|---|---:|---:|
| 原始 running statistics | 77.939% | 72.324% |
| `update_bn` 重新统计后 | 92.358% | 86.734% |
| 变化 | +14.419 个百分点 | +14.410 个百分点 |

这个对照强烈支持：模型权重本身并没有在某一轮突然完全失效，`eval()` 使用的 BN 运行统计量不准确，是早中期验证结果异常的重要原因。

不过，这不能推出“所有使用 BatchNorm 的训练都必须调用 `update_bn`”。BN 失配还会受到学习率、特征分布变化速度、batch 顺序、增强强度等因素影响。

### V4：结构、初始化、调度器与逐轮 BN 校准

V4 对训练流程做了较完整的修正：

- 降采样残差捷径由单独的 1×1 Conv 改为 `1×1 Conv + BatchNorm`；
- Conv 使用适合 ReLU 的 Kaiming 初始化，Linear 使用 Xavier 初始化；
- SGD 加入 `momentum=0.9` 和 `weight_decay=5e-4`；
- 使用 `CosineAnnealingLR(T_max=30, eta_min=1e-4)`；
- 每个 epoch 结束后，用训练折的确定性图片执行 `update_bn`，然后再次验证。

逐轮校准后的第一折验证准确率在第 29 轮达到约 93.16%，第 30 轮约 93.14%，后期曲线明显比原始 `eval()` 结果稳定。

V4 说明 `update_bn` 能把“权重能力”和“BN 运行统计误差”分开。但它每轮需要额外完整遍历一次训练折，还要再次遍历验证折，计算量明显增加；并且校准后的 running statistics 会继续保留到下一轮训练中，使实验不再只是纯粹的只读诊断。

于是 V5 用完全相同的主要配置去掉逐轮 BN 校准，检验它是否真有必要。

### V5：取消逐轮 `update_bn`

V5 使用 batch size 64、30 个 epoch、`T_max=30`，但不再每轮调用 `update_bn`。

结果显示，原始验证曲线在早中期仍有波动，但随着余弦退火将学习率逐渐降下来，后期明显稳定：第一折第 28 轮验证准确率约 93.22%，第 29、30 轮分别约 93.19% 和 93.11%。这一结果与 V4 校准后的最终水平十分接近。

这支持了一个更完整的解释：

> 高学习率阶段，权重和内部特征分布快速改变，BN 的运行统计量容易滞后；进入低学习率阶段后，权重变化减小，特征分布和 running statistics 会逐步稳定，因此最终模型未必需要额外校准。

V5 因而成为后续实验的主要基线。

### V6：将 batch size 增加到 128

V6 只把 batch size 从 64 增加到 128，希望每个批次包含更多样本，从而减少 BatchNorm 当前批次统计量的噪声。

结果并没有更好：第一折最佳验证准确率约 91.75%，第 30 轮约 91.72%，而且中期仍存在明显波动。

原因不能简单概括为“大 batch 不好”。当 batch size 翻倍时：

- 每个 batch 的均值和方差通常更稳定；
- 但每个 epoch 的参数更新次数约减半；
- 总 epoch 不变意味着总优化步数约减半；
- `scheduler.step()` 仍按 epoch 调用，学习率却在更少的参数更新后降到了同样的最低值。

所以 V6 同时改变了 BN 的统计质量和优化步数预算，不能视作严格单变量实验。

### V7：大 batch 下延长余弦周期

V7 保持 batch size 128 和 30 个 epoch，只把 `T_max` 从 30 改为 60，希望让学习率下降得慢一些。

余弦退火公式为：

$$
\eta_t=\eta_{min}+\frac{1}{2}(\eta_{max}-\eta_{min})
\left(1+\cos\frac{\pi t}{T_{max}}\right)
$$
当初始学习率为 0.05、`eta_min=1e-4`、`T_max=60`，只训练 30 轮时，训练正好停在余弦曲线中点，末轮学习率约为：

$$
0.0001+\frac{0.05-0.0001}{2}=0.02505
$$
因此 V7 在结束时学习率仍然较高，没有进入充分的低学习率精调阶段。第一折第 30 轮验证准确率约 85.34%，训练准确率约 94.89%，表现明显不如 V5/V6。

这个结果说明“降低得慢一些”本身不是目标，真正需要的是让总训练过程同时包含足够的优化步数和一个完整的低学习率收敛阶段。

### V8：延长到 40 轮并完成正式五折

V8 回到 V5 的 batch size 64，将训练轮数从 30 增加到 40，并设置 `T_max=40`。其最终配置为：

| 项目 | 配置 |
|---|---|
| 模型 | 自定义、从零训练的 ResNet18 |
| 输入/输出 | RGB 三通道 / 176 类 |
| 图像尺寸 | 224×224 |
| 交叉验证 | 5 折 StratifiedKFold，seed=42 |
| 优化器 | SGD |
| 初始学习率 | 0.05 |
| 动量 | 0.9 |
| 权重衰减 | 5e-4 |
| batch size | 64 |
| epoch | 40 |
| 调度器 | CosineAnnealingLR，`T_max=40`，`eta_min=1e-4` |
| BN 校准 | 不逐轮调用 `update_bn` |
| 设备 | 单张 Tesla T4；第二张 T4 未使用 |

V8 第 39 轮的五折验证准确率为：

| 折数 | 第 39 轮验证准确率 |
|---:|---:|
| 1 | 93.7619% |
| 2 | 93.8981% |
| 3 | 93.3261% |
| 4 | 93.5967% |
| 5 | 93.4060% |
| **平均** | **93.5978%** |

折间总体标准差约为 0.2134 个百分点，说明五折结果相当一致。第 40 轮五折平均准确率为 93.5923%，与第 39 轮几乎相同，模型已经进入平台期。

各折自身最高点分别出现在第 40、40、39、35、39 轮。正式选择训练轮数时，没有选择某一折偶然达到的最高点，而是选择**同一 epoch 在五折上的平均验证准确率最高点**，因此最终选择第 39 轮。

代码中的 `best_epoch=38` 是从 0 开始的下标，实际代表第 39 轮。使用全部 18,353 张训练图片重新训练 39 轮后，末轮训练 loss 约为 0.05608，训练准确率约为 98.8176%。模型随后生成 8,800 个测试预测和 `(8800, 2)` 的 `submission.csv`。

## 4. 对“验证曲线为什么震荡”的最终认识

本实验中的震荡不是单一原因造成，而是以下因素共同作用：

1. **高学习率下参数更新较大。** 相邻 epoch 的模型可能处在损失曲面的不同位置，验证指标不保证单调变化。
2. **内部特征分布持续漂移。** 卷积权重变化会改变后续 BN 层输入的分布。
3. **BN 运行统计存在滞后。** `train()` 使用当前 batch 的统计量，`eval()` 使用历史指数移动平均；二者在快速变化阶段可能不一致。
4. **随机增强和 batch 顺序带来随机性。** 每轮模型看到的图像姿态和批次组合不同。
5. **数据规模和类别数量。** 176 类任务中，少量样本预测变化就可能造成可见的准确率跳动。

因此，“后期学习率降低后震荡减少”的理解是正确的，但应表达为：

> 学习率降低会减小权重更新幅度，使内部特征分布变化变慢，从而同时改善模型参数的稳定性和 BatchNorm running statistics 的跟踪效果。

这不等于每次波动都由 BatchNorm 引起，也不意味着增加 epoch 一定能无限提高准确率。当训练已经进入平台期后，继续训练可能只有很小收益，甚至开始过拟合。

## 5. 关于 `update_bn` 的结论

`update_bn(train_iter, net, device)` 会清空 BatchNorm 已有的运行统计量，并使用给定数据重新前向传播，通过累计平均重新计算 `running_mean` 和 `running_var`。该过程：

- 不计算梯度；
- 不更新卷积、全连接层权重；
- 不更新 BN 的可学习参数 γ、β；
- 会修改 BN 的 `running_mean`、`running_var` 和 `num_batches_tracked`。

正确的校准数据必须来自训练折，而且最好使用无随机增强的确定性 transform。不能使用验证集执行 `update_bn`，否则会把验证集分布写进模型状态，造成数据泄漏。

本实验得到的实际结论是：

- 在早中期高学习率阶段，`update_bn` 可显著改善推理指标并帮助诊断问题；
- 在 V5/V8 的后期低学习率阶段，不进行逐轮校准也能达到稳定结果；
- 因此不需要把 `update_bn` 当作每个 BatchNorm 模型的固定步骤；
- 若最终 checkpoint 的 `eval()` 表现明显低于训练模式下的 batch 统计结果，可在训练完成后只校准一次并重新验证。

模型通过 `state_dict()` 保存时，BN 的 `running_mean`、`running_var` 和 `num_batches_tracked` 也会一同保存；加载后仍需调用 `model.eval()` 才会使用它们进行推理。

## 6. 实验设计中值得保留的做法

### 6.1 训练与验证使用不同 Dataset、相同索引

训练 Dataset 使用随机增强，验证 Dataset 使用确定性变换。两者对应同一份 CSV 和相同顺序，再使用相同的折索引构造 Subset。这种设计既避免验证数据增强，也不需要复制图片文件。

### 6.2 使用分层五折选择统一训练轮数

交叉验证的目标是评估配置，而不是保存五个模型后直接挑一个最幸运的模型。当前流程采用每个 epoch 的五折平均准确率选择轮数，然后从头使用全部训练集训练相同轮数，逻辑是完整的。

### 6.3 保存完整 checkpoint

checkpoint 不只保存 `model_state_dict`，还保存类别映射、均值、标准差、图像大小和验证结果，能够避免预测阶段标签映射或预处理不一致。

建议今后把轮数命名得更明确，例如同时保存：

```python
"best_epoch_index": best_epoch,
"best_epoch_number": best_epoch + 1,
```

这样可以避免 0 基下标和实际轮数混淆。

### 6.4 固定随机种子

正式 V8 同时设置了 Python、NumPy、PyTorch CPU 和 CUDA 随机种子。仅给 K 折设置 `random_state` 只能固定数据划分，不能固定初始化、DataLoader 顺序和数据增强。

## 7. 当前实验的局限

1. **部分版本一次改变了多个变量。** V4 同时改变捷径结构、初始化、调度器和 BN 校准，因此它能证明组合方案有效，却不能严格量化每一项贡献。
2. **V1–V7 多为单折探索。** 单折可快速排查问题，但小幅准确率差异不能视为可靠结论。
3. **均值和标准差使用全部训练集统计。** Kaggle 场景中通常可以接受，因为没有使用标签；若进行严格研究，应在每一折只用该折训练部分统计，彻底避免验证分布参与预处理参数估计。
4. **V8 的调度周期和总 epoch 同时改变。** `T_max=epoch` 会让最低学习率永远出现在训练末端，因此“最佳点总在最后几轮”部分是调度器设计导致的，不代表模型天然必须在最后一轮才最好。
5. **尚未做严格消融。** batch size 变化时总优化步数也变化，不能仅根据 V5/V6 断言某个 batch size 在所有条件下更优。
6. **仅使用单卡。** Kaggle 提供两张 T4，但当前 `cuda:0` 代码只使用第一张；这影响速度，不影响模型正确性。

## 8. 下一阶段建议

如果继续优化，建议按以下优先级进行，并且每次尽量只改变一个主要变量：

1. **先提交 V8，记录公开榜分数。** 交叉验证指标只是离线估计，最终仍要观察 Kaggle 分数。
2. **加入最佳 checkpoint/early stopping。** 即使最终仍需全数据重训，也应保留每折最佳状态和完整曲线，方便诊断。
3. **尝试 `ReduceLROnPlateau`。** 它会在验证指标长期不改善时降低学习率，可用来对比固定余弦计划；但必须明确监控 `valid_loss` 还是 `valid_acc`。
4. **做真正公平的 batch 对照。** 若 batch 由 64 改为 128，可同步增加 epoch 或按 optimizer step 设计学习率计划，使总更新步数接近。
5. **优化模型细节。** Conv 后紧接 BatchNorm 时可设置 `bias=False`，减少没有必要的偏置参数。
6. **迁移学习对照。** 使用 ImageNet 预训练 ResNet18，并采用 ImageNet 均值/标准差，比较从零训练与迁移学习的收敛速度和最终准确率。
7. **更规范地保存实验记录。** 每版保存配置 JSON、逐 epoch CSV、随机种子、运行时间和 Kaggle 分数，避免只依赖 notebook 输出。

如果目标是优先提高比赛成绩，迁移学习通常比继续微调从零训练的 ResNet18 更值得尝试；如果目标是理解完整训练流程，则当前 V1–V8 已经完成了一条很有价值的“观察现象—提出猜想—设计对照—修正解释”的实验链条。

---

## 9. 最终结论

八个版本中最重要的进展并不是单纯把准确率提高到约 93.60%，而是逐步澄清了验证震荡的来源：

- 数据增强和标准化改善泛化，但不能独自消除震荡；
- 分层 K 折提高评估可靠性，但未分层不是同一折跨 epoch 波动的主要原因；
- BatchNorm 运行统计量失配是重要因素，`update_bn` 是有效的诊断和校准工具；
- 更根本的稳定因素是合理的优化过程，尤其是足够的训练步数和低学习率收敛阶段；
- 增大 batch size 时必须同时考虑总更新步数和学习率调度，不能只看 BN 统计是否更稳定；
- V8 使用分层五折、完整余弦退火和 40 轮训练，在不逐轮校准 BN 的情况下得到稳定的五折结果，并完成了全数据重训、模型保存和测试集提交。
- 为了降低验证准确率震荡，可以逐步降低lr，使得running参数波动小一些

因此，当前可将 **V8 作为从零训练 ResNet18 的正式基线版本**，后续迁移学习、数据增强或优化器实验都应尽量以 V8 为对照。
